🔧 Environment Configuration Instructions

  • APP_NAME=ExoDesk – Set the name of your application.
  • APP_ENV=production – Set to production for live environments.
  • APP_URL=your_full_website_url – Replace with your full website URL (e.g., https://example.com).
  • DB_CONNECTION=mysql – Leave as mysql unless using another DB system.
  • DB_HOST=your_database_host_name – Replace with your database host (e.g., 127.0.0.1 or server IP).
  • DB_PORT=3306 – Default MySQL port. Change only if necessary.
  • DB_DATABASE=your_database_name – Your database name.
  • DB_USERNAME=your_database_host_username – Username used to access the database.
  • DB_PASSWORD=your_database_host_password – Password for the database user.
  • CRON_JOB_TOKEN='put_your_token_here' – Replace with a secure token used to run cron jobs.
  • ENABLE_EMAIL_NOTIFICATIONS=false – Set to true to enable email notifications.
  • MAIL_MAILER=smtp – Use smtp to send emails.
  • MAIL_HOST=your_mail_host – Your mail server host (e.g., smtp.gmail.com).
  • MAIL_PORT=587 – Use 587 for TLS or 465 for SSL.
  • MAIL_USERNAME=your_email_address – Your email address or login for SMTP.
  • MAIL_PASSWORD=your_mail_password – Your SMTP password.
  • MAIL_ENCRYPTION=tls – Encryption method; typically tls.
  • MAIL_FROM_ADDRESS=your_email_address – Sender email address for outgoing emails.
  • MAIL_FROM_NAME="${APP_NAME}" – Uses APP_NAME (e.g., "ExoDesk") as the sender name.

Cron Jobs Configuration for Email

📧 Cron Job Configuration for Email – Hostinger

  • Login to your Hostinger control panel.
  • From the left sidebar, navigate to:
    Advanced → Cron Jobs
  • Under Create a New Cron Job, select the Custom option.
  • In the Command to run field, enter:
    wget -q -O - "https://exodesk.nepexo.com/cron?token=eeee"
    Replace eeee with your actual CRON_JOB_TOKEN from the .env file.
  • Under Common options, choose:
    Twice an hour (0,30 * * * *)
  • Confirm the following time settings:
    • Minute: Every 30 minutes (0,30)
    • Hour: Every Hour (*)
    • Day: Every Day (*)
    • Month: Every Month (*)
    • Weekday: Every Weekday (*)
  • Click the Save button to apply the cron job.

✅ Additional Notes

  • Make sure your .env file includes:
    ENABLE_EMAIL_NOTIFICATIONS=true
    CRON_JOB_TOKEN=your_secure_token
  • This cron job ensures automated email notifications and scheduled tasks run every 30 minutes.
  • Use a secure, random token to protect the cron endpoint from unauthorized access.

Roles & Permissions

In this system, Roles & Permissions define how users interact with various modules and features. Each role is assigned a specific set of permissions that align with their responsibilities, ensuring secure and organized access control across the application.

🎯 Why Roles & Permissions Matter

  • ✅ Ensure users only access features relevant to their duties
  • ✅ Prevent unauthorized actions and protect sensitive data
  • ✅ Improve usability by simplifying interfaces for different roles
  • ✅ Allow scalable, role-based management for large teams

👥 User Roles Overview

🔸 Super Admin

  • Full access to all modules and system settings
  • Can create, update, and delete users, roles, and configurations
  • Manages overall system operations and global permissions

🔸 Admin

  • Access to most management features except high-level system settings
  • Manages teams, modules, data, and day-to-day operations
  • Can assign roles to users under their scope

🔸 Agent

  • Works on assigned tasks or tickets
  • Has limited access based on assignments and scope
  • Can communicate with customers or other team members

🔸 Customer

  • End-users of the platform
  • Can submit tickets, view responses, and manage their own profiles
  • Has access to only relevant customer-facing features

🔧 Permission System

Each permission controls access to a specific action or feature, such as:

  • view_dashboard
  • create_ticket
  • manage_users
  • edit_settings

Permissions are grouped and assigned to roles. This structure allows for:

  • Easy updates when responsibilities change
  • Custom role creation for specialized access needs
  • Full audit control over who can do what within the system

Users List

This section explains how to manage users within the system using Create, Read, Update, and Delete (CRUD) functions.

➕ Create New User

  • Go to the Users section from the sidebar menu.
  • Click on the "Add New User" or "Create" button.
  • Fill in the required fields such as name, email, role, and password.
  • Click "Save" to create the user.

👁️ View Users (Read)

  • Navigate to the Users menu.
  • All registered users will be listed in a table view.
  • You can see details like name, email, role, status, and creation date.

✏️ Update User

  • In the user list, click the "Edit" icon/button next to the user you want to update.
  • Modify the necessary fields (e.g., name, email, role).
  • Click "Update" to save the changes.

🗑️ Delete User

  • Find the user in the list you want to remove.
  • Click the "Delete" icon/button.
  • Confirm the deletion when prompted.
  • Warning: Deleting a user is permanent and cannot be undone.

🔐 Assigning Roles

  • During user creation or editing, select a role from the dropdown (e.g., Admin, Agent, Customer).
  • Roles define what permissions and access each user has within the system.

✅ Best Practices

  • Ensure each user has a unique email and secure password.
  • Assign roles carefully to avoid unauthorized access.
  • Regularly review and update user access as needed.

Manage Tickets

This section explains how to manage support tickets within the system. Depending on your role (Customer, Agent, or Admin), the available actions may vary.

📥 View Tickets

  • Navigate to the Tickets menu from the sidebar.
  • Tickets are listed in a table with columns such as Subject, Status, Priority, Assigned Agent, and Created Date.
  • Use filters to sort by department, category, status, or assigned agent.

➕ Create a Ticket (Customer)

  • Click "New Ticket".
  • Select a relevant Department and Category.
  • Enter the subject and description of the issue.
  • Attach files if needed, then click Submit.

📂 Departments & Categories

  • Departments help route tickets to the right team (e.g., Sales, Technical Support).
  • Categories define the type of issue (e.g., Login Problem, Payment Issue).
  • Admins can create and manage departments/categories in system settings.

📤 Show & Reply to Ticket

  • Click on a ticket to open its detailed view.
  • Agents/Admins can view the full conversation and add replies.
  • Use the Reply field to respond or request more info from the customer.
  • Replies can include text, images, or file attachments.

👤 Assign Tickets

  • Admins can assign tickets to specific agents or leave them unassigned.
  • Use the dropdown menu in the ticket view to select an available agent.
  • Assigned agents will be notified and will see the ticket in their queue.

⚠️ Escalate Tickets

  • Admins or agents can escalate tickets if additional attention or a higher authority is required.
  • Escalated tickets are flagged and optionally reassigned to a supervisor or admin.
  • Escalation status is visible in the ticket timeline/history.

✏️ Update Ticket (Status, Priority, Notes)

  • Agents/Admins can change ticket status (e.g., Open, In Progress, Closed).
  • Priority levels (Low, Medium, High, Critical) can be set based on issue urgency.
  • Internal notes can be added without notifying the customer.

✅ Close Ticket

  • Once resolved, change the ticket status to Closed.
  • Closed tickets are archived but can still be viewed in read-only mode.

📊 Ticket History

  • Every ticket contains a full audit log of actions: replies, status changes, assignments, and escalations.
  • Admins and agents can use this log to track the timeline of resolution.

🧾 Notes

  • Customers can only view and reply to their own tickets.
  • Agents manage tickets assigned to them and can escalate or request help.
  • Admins have full control over all tickets, users, departments, and escalations.
