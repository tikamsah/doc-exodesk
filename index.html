🔧 Environment Configuration Instructions

  • APP_NAME=ExoDesk – Set the name of your application.
  • APP_ENV=production – Set to production for live environments.
  • APP_URL=your_full_website_url – Replace with your full website URL (e.g., https://example.com).
  • DB_CONNECTION=mysql – Leave as mysql unless using another DB system.
  • DB_HOST=your_database_host_name – Replace with your database host (e.g., 127.0.0.1 or server IP).
  • DB_PORT=3306 – Default MySQL port. Change only if necessary.
  • DB_DATABASE=your_database_name – Your database name.
  • DB_USERNAME=your_database_host_username – Username used to access the database.
  • DB_PASSWORD=your_database_host_password – Password for the database user.
  • CRON_JOB_TOKEN='put_your_token_here' – Replace with a secure token used to run cron jobs.
  • ENABLE_EMAIL_NOTIFICATIONS=false – Set to true to enable email notifications.
  • MAIL_MAILER=smtp – Use smtp to send emails.
  • MAIL_HOST=your_mail_host – Your mail server host (e.g., smtp.gmail.com).
  • MAIL_PORT=587 – Use 587 for TLS or 465 for SSL.
  • MAIL_USERNAME=your_email_address – Your email address or login for SMTP.
  • MAIL_PASSWORD=your_mail_password – Your SMTP password.
  • MAIL_ENCRYPTION=tls – Encryption method; typically tls.
  • MAIL_FROM_ADDRESS=your_email_address – Sender email address for outgoing emails.
  • MAIL_FROM_NAME="${APP_NAME}" – Uses APP_NAME (e.g., "ExoDesk") as the sender name.

Cron Jobs Configuration for Email

📧 Cron Job Configuration for Email – Hostinger

  • Login to your Hostinger control panel.
  • From the left sidebar, navigate to:
    Advanced → Cron Jobs
  • Under Create a New Cron Job, select the Custom option.
  • In the Command to run field, enter:
    wget -q -O - "https://exodesk.nepexo.com/cron?token=eeee"
    Replace eeee with your actual CRON_JOB_TOKEN from the .env file.
  • Under Common options, choose:
    Twice an hour (0,30 * * * *)
  • Confirm the following time settings:
    • Minute: Every 30 minutes (0,30)
    • Hour: Every Hour (*)
    • Day: Every Day (*)
    • Month: Every Month (*)
    • Weekday: Every Weekday (*)
  • Click the Save button to apply the cron job.

✅ Additional Notes

  • Make sure your .env file includes:
    ENABLE_EMAIL_NOTIFICATIONS=true
    CRON_JOB_TOKEN=your_secure_token
  • This cron job ensures automated email notifications and scheduled tasks run every 30 minutes.
  • Use a secure, random token to protect the cron endpoint from unauthorized access.

Roles & Permissions

In this system, Roles & Permissions define how users interact with various modules and features. Each role is assigned a specific set of permissions that align with their responsibilities, ensuring secure and organized access control across the application.

🎯 Why Roles & Permissions Matter

  • ✅ Ensure users only access features relevant to their duties
  • ✅ Prevent unauthorized actions and protect sensitive data
  • ✅ Improve usability by simplifying interfaces for different roles
  • ✅ Allow scalable, role-based management for large teams

👥 User Roles Overview

🔸 Super Admin

  • Full access to all modules and system settings
  • Can create, update, and delete users, roles, and configurations
  • Manages overall system operations and global permissions

🔸 Admin

  • Access to most management features except high-level system settings
  • Manages teams, modules, data, and day-to-day operations
  • Can assign roles to users under their scope

🔸 Agent

  • Works on assigned tasks or tickets
  • Has limited access based on assignments and scope
  • Can communicate with customers or other team members

🔸 Customer

  • End-users of the platform
  • Can submit tickets, view responses, and manage their own profiles
  • Has access to only relevant customer-facing features

🔧 Permission System

Each permission controls access to a specific action or feature, such as:

  • view_dashboard
  • create_ticket
  • manage_users
  • edit_settings

Permissions are grouped and assigned to roles. This structure allows for:

  • Easy updates when responsibilities change
  • Custom role creation for specialized access needs
  • Full audit control over who can do what within the system

Users List

This section explains how to manage users within the system using Create, Read, Update, and Delete (CRUD) functions.

➕ Create New User

  • Go to the Users section from the sidebar menu.
  • Click on the "Add New User" or "Create" button.
  • Fill in the required fields such as name, email, role, and password.
  • Click "Save" to create the user.

👁️ View Users (Read)

  • Navigate to the Users menu.
  • All registered users will be listed in a table view.
  • You can see details like name, email, role, status, and creation date.

✏️ Update User

  • In the user list, click the "Edit" icon/button next to the user you want to update.
  • Modify the necessary fields (e.g., name, email, role).
  • Click "Update" to save the changes.

🗑️ Delete User

  • Find the user in the list you want to remove.
  • Click the "Delete" icon/button.
  • Confirm the deletion when prompted.
  • Warning: Deleting a user is permanent and cannot be undone.

🔐 Assigning Roles

  • During user creation or editing, select a role from the dropdown (e.g., Admin, Agent, Customer).
  • Roles define what permissions and access each user has within the system.

✅ Best Practices

  • Ensure each user has a unique email and secure password.
  • Assign roles carefully to avoid unauthorized access.
  • Regularly review and update user access as needed.

Manage Tickets

This section explains how to manage support tickets within the system. Depending on your role (Customer, Agent, or Admin), the available actions may vary.

📥 View Tickets

  • Navigate to the Tickets menu from the sidebar.
  • Tickets are listed in a table with columns such as Subject, Status, Priority, Assigned Agent, and Created Date.
  • Use filters to sort by department, category, status, or assigned agent.

➕ Create a Ticket (Customer)

  • Click "New Ticket".
  • Select a relevant Department and Category.
  • Enter the subject and description of the issue.
  • Attach files if needed, then click Submit.

📂 Departments & Categories

  • Departments help route tickets to the right team (e.g., Sales, Technical Support).
  • Categories define the type of issue (e.g., Login Problem, Payment Issue).
  • Admins can create and manage departments/categories in system settings.

📤 Show & Reply to Ticket

  • Click on a ticket to open its detailed view.
  • Agents/Admins can view the full conversation and add replies.
  • Use the Reply field to respond or request more info from the customer.
  • Replies can include text, images, or file attachments.

👤 Assign Tickets

  • Admins can assign tickets to specific agents or leave them unassigned.
  • Use the dropdown menu in the ticket view to select an available agent.
  • Assigned agents will be notified and will see the ticket in their queue.

⚠️ Escalate Tickets

  • Admins or agents can escalate tickets if additional attention or a higher authority is required.
  • Escalated tickets are flagged and optionally reassigned to a supervisor or admin.
  • Escalation status is visible in the ticket timeline/history.

✏️ Update Ticket (Status, Priority, Notes)

  • Agents/Admins can change ticket status (e.g., Open, In Progress, Closed).
  • Priority levels (Low, Medium, High, Critical) can be set based on issue urgency.
  • Internal notes can be added without notifying the customer.

✅ Close Ticket

  • Once resolved, change the ticket status to Closed.
  • Closed tickets are archived but can still be viewed in read-only mode.

📊 Ticket History

  • Every ticket contains a full audit log of actions: replies, status changes, assignments, and escalations.
  • Admins and agents can use this log to track the timeline of resolution.

🧾 Notes

  • Customers can only view and reply to their own tickets.
  • Agents manage tickets assigned to them and can escalate or request help.
  • Admins have full control over all tickets, users, departments, and escalations.

Knowledge Base

This section explains how to manage Knowledge Base (KB) categories in the system. Depending on your role (Content Editor, Support Agent, or Admin), the available actions may vary.

📚 Knowledge Base Category Management

📖 View Categories

  • Navigate to the Knowledge Base section in the admin panel.
  • Click on the Categories tab to see a list of all existing categories.
  • Each category displays its name, description, number of articles, and visibility status.

➕ Create a New Category

  • Click the "Add Category" or "New Category" button.
  • Enter a descriptive Name for the category (e.g., “Billing”, “Getting Started”).
  • Optionally, provide a Description to guide users.
  • Choose the Visibility level (Public, Internal, or Restricted).
  • Click Save to publish the category.

✏️ Edit Category

  • Select the category you wish to update from the list.
  • Click the Edit (✏️) button.
  • Modify the name, description, visibility, or sort order as needed.
  • Click Save Changes.

🗑️ Delete Category

  • Only Admins can delete categories.
  • Navigate to the category and click the Delete (🗑️) icon.
  • Confirm deletion when prompted.
  • Articles in deleted categories will either be unassigned or archived, depending on system rules.

📂 Category Structure

  • Categories organize related articles for easy user navigation.
  • Some systems support Subcategories for deeper structure (e.g., “Billing” → “Invoices”).
  • Admins can drag-and-drop categories to reorder them in the UI.

🔍 Filter & Search

  • Use search filters to find categories by keyword, visibility, or number of articles.
  • This helps large content teams quickly locate or manage categories.

👥 Role-Based Access

  • Content Editors can create and edit categories, but may not delete them.
  • Support Agents can view and suggest edits but have limited category management rights.
  • Admins have full control over all category actions and visibility settings.

📊 Category Analytics

  • Some platforms include basic metrics like article count, views, and helpfulness per category.
  • Admins can use this data to reorganize or improve content structure.

🧾 Notes

  • Categories improve user navigation and article discovery.
  • Regular audits are recommended to merge duplicates or clean up unused categories.
  • Use short, clear, and meaningful names for maximum impact.

📄 Knowledge Base Article Management

📖 View Articles

  • Navigate to the Knowledge Base section in the admin dashboard.
  • Select the Articles tab to view a list of all articles.
  • Each entry includes Title, Category, Status, Author, and Last Updated.
  • Use filters to view articles by category, author, status, or keyword.
  • The article view page includes ratings (e.g., helpful/unhelpful) and comments from users to gather feedback.

➕ Create a New Article

  • Click the "New Article" or "Add Article" button.
  • Enter a descriptive Title and choose a Category.
  • Write your content using the rich text editor. You can include text, images, videos, links, and code blocks.
  • Assign relevant Tags to improve searchability.
  • Select the Status (Draft, Published, or Archived).
  • Click Save or Publish to complete.

✏️ Edit Article

  • Locate the article from the list and click the Edit (✏️) icon.
  • Update the title, body content, category, tags, or visibility as needed.
  • Click Save Changes or Update.

🗑️ Delete Article

  • Admins or authorized editors can delete articles.
  • Open the article and click the Delete (🗑️) button.
  • Confirm deletion when prompted. Deleted articles may go to a trash/archive bin depending on system settings.

📂 Organize Articles by Category

  • Each article must belong to one category. Choose the most relevant category during creation.
  • Admins can later move articles to a different category if needed.
  • Articles within the same category are shown together in the user-facing knowledge base.

🔍 Search Optimization

  • Use clear titles that reflect common user questions.
  • Assign meaningful tags and avoid duplicates.
  • Include relevant keywords in both the title and content body to improve search indexing.

👥 Role-Based Access

  • Content Editors can create, edit, and publish articles within assigned categories.
  • Support Agents can suggest edits and submit draft articles.
  • Admins have full access to create, edit, publish, archive, and delete articles.

📊 Article Analytics

  • Most platforms track views, likes/dislikes, and feedback per article.
  • User comments and ratings help measure article helpfulness.
  • Use analytics to identify top-performing content and areas needing improvement.

🧾 Notes

  • Keep articles clear, concise, and focused on solving a specific problem or explaining a feature.
  • Use bullet points, headings, and formatting to improve readability.
  • Review and update articles regularly to keep content accurate and helpful.

📢 Notifications

  • Users may receive email or in-app notifications when:
    • A new article is published in a category they follow.
    • An article they authored or edited is approved or updated.
    • Someone comments on an article they authored or follow.

📈 Reports

  • Admins and content managers can access detailed reports to track article performance over time.
  • Common report types include:
    • Views Report – shows total and unique views per article.
    • Feedback Report – aggregates helpful/unhelpful votes or satisfaction scores.
    • Engagement Report – includes comments, shares, and reading time metrics.
    • Author Activity Report – tracks article contributions and edits by user.
    • Category Performance Report – compares article activity across categories.
  • Reports help identify:
    • Top-performing and underperforming content.
    • Articles that need updating or archiving.
    • Content gaps based on search terms with no results.
  • Reports can usually be filtered by date range, category, author, or status.

📧 Mail Configuration / SMTP Setup – cPanel

This guide explains how to create and configure an SMTP email account using cPanel.

🛠️ Step 1: Log in to cPanel

Access your hosting account and log into the cPanel dashboard.

📨 Step 2: Create an Email Account

  1. Go to Email Accounts in cPanel.
  2. Click Create.
  3. Fill in the form:
    • Username: e.g., info, test, or hr
    • Domain: Select the appropriate domain (if multiple are available)
    • Password: Set a strong password or use the generator
  4. Click Create to finish.

📌 This will create an email like test@yourdomain.com

⚙️ Step 3: Get SMTP Settings

  1. Go to Email Accounts again.
  2. Find your newly created email and click Connect Devices.
  3. Under Mail Client Manual Settings, you’ll find the SMTP details.

📋 SMTP Configuration Example

Input Value
QUEUE_MAIL Select true or false. If true, run: php artisan queue:work
MAIL_DRIVER_TYPE Select MAIL MAILER or MAIL DRIVER
MAIL_DRIVER sendmail: Use if your server has a local mail server (e.g., Postfix or Exim).
smtp: Use for external mail services (e.g., Gmail, Mailgun, hosting SMTP).
MAIL_HOST mail.yourdomain.com
MAIL_PORT 587
MAIL_USERNAME test@yourdomain.com
MAIL_PASSWORD Your email password
MAIL_ENCRYPTION tls
MAIL_FROM_ADDRESS yourmail@gmail.com
MAIL_FROM_NAME Your project or app name

🛠️ Apply these values under System Settings → Mail Configuration

⚠️ Queue Mail Execution Notes

  • If you enable QUEUE_MAIL = true, you must run the queue command:
  • php artisan queue:work
  • Make sure the command is run from your project root. For example:
    /home/u186958312/domains/yourdomain.com/public_html
  • Alternative: If you can’t run the CLI command manually, open this URL in a browser to trigger it:
    yourdomain.com/queue-work
  • Important: If QUEUE_MAIL is set to true but the command isn't executed, your email system will not function properly.

📧 Mail Configuration / SMTP Setup – Gmail

This guide explains how to configure SMTP for sending emails via a Gmail account. It involves enabling 2-Step Verification and generating an App Password.

🔐 Step 1: Enable 2-Step Verification

  1. Visit https://myaccount.google.com
  2. Click Security from the left-hand menu.
  3. Under Signing in to Google, enable 2-Step Verification.

Follow the prompts to complete setup using your phone or other options.

🔑 Step 2: Generate an App Password

  1. After enabling 2-Step Verification, go to https://myaccount.google.com/apppasswords
  2. Sign in if prompted.
  3. Under Select the app, choose Other (Custom name).
  4. Enter a name like SMTP App and click Generate.

Google will show you a 16-character app password. Copy this — it will be your SMTP password.
